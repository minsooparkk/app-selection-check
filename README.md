# 앱-선정-점검 (app-selection-check)

업무에 쓰는 소프트웨어 앱을 **"내 자료를 스크립트로 꺼낼 수 있는가"** 로 점검하는 AI 스킬입니다(Claude Code 등 `SKILL.md` 를 읽는 도구용).

> Workflow 설계의 대원칙: "Garbage in, Garbage out". Input 이 업무 품질의 8할을 차지합니다.
> 잘 "처리"하는 것보다 좋은 데이터를 모으는 시스템을 설계하는 것이 먼저입니다.

## 하는 일

1. 컴퓨터에 설치된 앱을 모두 뽑습니다(macOS·Windows). 웹으로만 쓰는 서비스는 사용자에게 물어 더합니다.
2. 앱마다 웹에서 **API·MCP** 를 제공하는지 확인합니다.
3. 없으면 **바꿀 수 없는 대형 플랫폼**인지, **내 컴퓨터에서 정형화**할 수 있는지 확인합니다.
4. 어느 기준에도 들지 않으면 **대안 앱**을 제시합니다.
5. 결과를 **확실한 것 · 불확실한 것 · 판단이 필요한 것**으로 나눠 보고합니다.

| 구분 | 뜻 | Input 관리 방법 |
|---|---|---|
| 1 유지(API·MCP) | 내 자료를 읽는 API 나 MCP 가 있음 | Deterministic 한 스크립트로 수집 |
| 2 유지(대형 플랫폼) | API·MCP 는 없지만 바꿀 수 없고, 내 컴퓨터에서 꺼낼 길이 있음 | 하루 한 번 내보내 정리 |
| 3 유지(로컬 정형화) | 파일이 내 컴퓨터에 남아 정형화할 수 있음(통화·회의 녹음 등) | 로컬 도구 + LLM |
| 교체 | 어느 기준에도 들지 않고 바꿀 수 있음 | API·MCP 가 있는 대안으로 |
| 포기 검토 | 어느 기준에도 들지 않고 바꿀 수도 없음 | 연결하지 않음(배보다 배꼽) |

## 설치

```
git clone https://github.com/minsooparkk/app-selection-check ~/.claude/skills/앱-선정-점검
```

Python 3.8 이상만 있으면 됩니다. 따로 설치할 것은 없습니다. 웹 검색 도구가 있는 환경에서 "내가 쓰는 앱 점검해줘"라고 말하면 됩니다.

## 구성

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 절차, 지켜야 할 선, 판단 기준 |
| `scripts/list_apps.py` | 설치된 앱 목록과 빈 근거 파일 만들기(판단 없음, 읽기 전용) |
| `scripts/judge.py` | 근거 파일에 기준을 적용해 구분과 확신 정도를 정함(판단 없음) |
| `references/기준.md` | 대원칙, 기본 원칙, 선정 기준의 풀이와 판정 규칙 |
| `examples/` | 합성 예시(가짜 앱 8개)의 근거 파일과 보고서 |

## 설계에서 지킨 것

- 구분은 모델이 정하지 않습니다. 모델은 웹에서 찾은 근거만 채우고 스크립트가 정합니다.
- "있다"는 공식 문서 주소가 있어야 인정합니다. 주소 없는 "있음"은 불확실로 내려갑니다.
- "API 가 있다"는 내 계정의 자료를 읽을 수 있을 때만 인정합니다(보내기 전용은 없는 것으로 봄).
- "대형 플랫폼"은 규모가 아니라 사용자가 바꿀 수 있는지로 보며, 사용자에게 묻습니다.

## 알아 둘 점

- 예시의 앱 이름과 주소는 모두 가짜입니다.
- Windows 의 앱 목록 뽑기는 아직 실제 기기에서 시험하지 않았습니다.
